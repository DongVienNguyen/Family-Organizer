# Legacy content write authority

Notes, schedules and documents retain their existing React/Express/SQLite flow. The same current live known actor and authenticated command context used by tasks now guard native content writes within the I01 synchronous gateway transaction. HTTP routes check a pure shape/version header before accessing request fields; importing the app factory does not import content storage/configuration through that guard.

| Domain | Existing create/edit/delete authority retained |
|---|---|
| Notes | All known roles create; creator or visible explicit edit-role grant edits; creator/Admin deletes |
| Schedules | Adult/Child create; visible creator/Admin edits or deletes; no Guest writes |
| Documents | Adults only; current visible creator/owner or shared Admin manages; no Admin private-document override |

Creator and timestamps belong to the server. Changed protected fields are denied even to managers; structurally unchanged full DTO fields are stripped or kept from the canonical record. Existing unknown extensions and unchanged canonical values remain, including historical owner IDs; new/changed unknown fields are rejected. A Notes content-edit grant does not authorize changing sharing or edit-role grants: those changes require the creator or an Admin who already has content editing authority. The sharing checkbox is disabled with localized associated help for delegated editors. Native management checks repeat HTTP authority rather than treating a caller-supplied actor ID as sufficient.

Changed fields are bounded plain typed values: title500, descriptions/notes20k, Markdown1MiB, tags40×128, known unique edit roles, valid calendar dates/time strings, known recurrence and weekdays0–6, live new document owner IDs and up to100 bounded attachment records. New attachments accept managed URLs with existing immutable media binding or external HTTP(S), and reject active data/javascript URLs. Existing upload MIME/size/root/file checks remain. Full-record clients preserve unchanged canonical values; this is not a migration deleting historical data. Document updates omitting files keep the previous attachment list; explicit empty files still clears it with existing orphan cleanup.

Notes/documents preserve genuine stale409 and gateway cached retry ordering; malformed id/version types or lengths return typed400. Schedules retain their existing version semantics; canonical revision work belongs to later P tasks. URL canonicalization now rejects decoded query/fragment delimiters instead of creating a metadata key that fails its next normalization. Ordinary generated ASCII, spaces and Unicode paths remain supported; legacy reserved fragment filenames remain on disk and require operator rename/rebind rather than a guessed binding or file deletion.
