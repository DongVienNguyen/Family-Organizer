# F04-b browser session/cache boundary

The existing React workflows use one internal request adapter. Each same-origin API/media request captures the current session revision, carries no-store, respects caller cancellation and a two-minute absolute request deadline. Signal combination/deadlines have explicit listener/timer cleanup and preserve browsers missing AbortSignal.any/timeout. A changed/expired session aborts owned requests; old Bearers are rejected before network access. Decoding JSON/text/blob/buffers/forms, clones and acquired stream readers checks the revision again. A late401 cannot log out a newer user. Public static/external requests preserve their behavior.

An outer BrowserSessionRoot subscribes to the boundary and keys the App tree by revision. Transition immediately unmounts the old tree, removing private App arrays and child-component/modal/search/AI state together. It waits for private storage cleanup before persisting/opening the next token. Failed/blocked cleanup stays closed with a translated inline retry. Bootstrap restores a saved token only after cleanup; cross-tab token changes reset the tree without recursive storage writes. Persisted theme, language and per-user weather choices remain; stale navigation/legacy user IDs clear. Root remount checks /api/auth/me before opening authenticated screens. Its bootstrap catch checks the captured revision before clearing login; an old aborted bootstrap cannot overwrite a newer session.

Service-worker controller/registration/install listeners are detached with each old tree, including registration resolving after unmount. Existing manual waiting-update behavior remains, with one security migration replacing v1–v4/API-caching workers automatically. The page requires a policy acknowledgement from its actual controlling worker before cleanup/session restore. Registration/control waits are bounded; an unavailable unsafe worker blocks session restore, with retry.

The v5 worker caches the public shell/assets only. API/uploads, Authorization requests, no-store/private responses and Authorization/star-varying/Set-Cookie responses never enter the cache. Activation removes Family-owned old caches while preserving unrelated origin applications. Logout/startup removes all Family API/private caches and private API/media/authenticated entries inside Family static caches, preserving public assets. Private IndexedDB names are family-organizer/family-private plus their hyphen-prefixed children; future private databases must use that registry. Known names are removed even without enumeration. Errors, blocked deletion and five-second deletion deadlines fail closed; unknown applications' databases are preserved.

Internal API/media HTTP responses, including denied requests, use no-store/Pragma/Expires and Vary Authorization. Static upload middleware cannot overwrite those headers; object/media authorization is still a subsequent F04 task. No long-lived access token is put in a URL. Existing ICS share links are separate legacy behavior still requiring the later ACL/credential audit.

Ruling: replace insecure URL-only private offline fallback with network-only API/media — required no-store and user isolation take precedence over that cache strategy — cost: private offline reuse requires a future explicit per-actor/expiry/ACL design. The public shell/assets still open offline; current in-memory state remains until logout or session transition.

Ruling: unmount the React tree at the session revision instead of manually clearing25 independently maintained arrays — this covers child state as well — cost: login restores via the existing auth-me check and transient state resets. No app or database rewrite.

Ruling: a one-time forced worker security migration and policy acknowledgement are required before restore — an old worker could otherwise refill private caches after cleanup — cost: first migration needs the updated worker available; later ordinary updates retain explicit waiting.

Private async exports capture the revision separately from network requests. A PDF that finishes after user switch cannot open a share sheet/download; failed shares cannot fall back under a different user. Backup download checks the captured revision immediately before creating its object URL. Existing authorized finance/emergency PDF delivery remains covered with synthetic renderer adapters.
