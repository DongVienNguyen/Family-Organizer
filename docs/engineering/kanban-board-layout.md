# Canonical Kanban columns and section archival (P08-b8)

This slice extends the internal authenticated Productivity board router. React/Express/SQLite, semantic schema8, frozen migration identities1–8 and Wallet1 remain the accepted baseline. No startup DDL, feature rollout, completion/reward writer, external API or deployment is added.

## Commands and authority

- `POST /api/productivity/boards/sections`: `{expectedRevision, input:{viewId,title,expectedViewRevision}}` creates one structural section and its canonical column in the same I01 transaction. Initial policy is off; it never changes Tasks.
- `POST /api/productivity/boards/columns/reorder`: input adds `columnId,beforeColumnId`. Shared integer rank metadata is reordered/rebalanced atomically, including built-in column positions. Canonical Task fields and Task revision are untouched.
- `POST /api/productivity/boards/columns/archive/preview`: `{viewId,columnId}` returns an opaque15-minute preview, whole-section scope, affected count and destinationNone. Only actual section columns may be archived. The preview is read-only and limited to1000 nondeleted Tasks; at most128 preview/expired owner references are retained until30minutes. Plans retain scalar IDs/revisions/digest rather than Task bodies.
- `POST /api/productivity/boards/columns/archive/apply`: `{expectedRevision,input:{viewId,columnId,previewId,expectedViewRevision}}` rechecks Task-set digest, section/list/view/board revisions and expiry inside I01. Nondeleted Tasks move toNone with stable IDs, lifecycle, approval and rewards; the canonical column becomes archived. HardNone WIP must have capacity for all incoming active roots. There is no implicit batch override. Built-inNone and workflow columns are not archivable.

Commands require a currently owned bound Kanban view and current list-manage authority before the idempotency cache and again inside the writer. Child/Guest and Member without manage grants cannot manage layout or obtain whole-section counts. The preview scope intentionally ignores the personal view filter; its count includes every nondeleted Task in the section, including subtasks. Non-Admin board projection still redacts canonical private WIP counts.

Exact UUID retries replay an already committed result only after fresh authority checks. Missing previews after restart are404; a committed archive retry can survive an archived target. Shared metadata changes emit catalog invalidation; archive emits existing scoped Task invalidation without leaking private Task body/identity to other roles. No notification or AI effect runs.

## Existing section writers

Common structural transaction helpers synchronize canonical section columns only at registered schema7/8, for an existing section board. Creating a section through the old editor API creates its column; renaming advances both column and board revisions, making card previews stale; archiving even an empty section marks its column and advances the board. Candidate tables at schema6 are inactive. Missing columns use bounded1000-column rank planning. All operations retain the owning I01 transaction and rollback cache, metadata and Tasks together. Exhausted list/section/column/board revisions fail closed.
