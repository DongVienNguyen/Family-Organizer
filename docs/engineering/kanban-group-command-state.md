# Grouped Kanban command ownership

The controller extends the physical confirmation owner with a grouped selection. A visible canonical Task may preview only the selected priority, assignee, due or tag dimension. The shared pure group-patch contract validates the intent. A tag source must match a visible projection, unless the caller explicitly chooses all-tags add/replace. Field-only changes remain available under non-rank sorting; an atomic rank anchor requires custom rank sorting and a visible reference in the derived destination group. Timed due anchors resolve using the selected view timezone.

The state stores a private cloned plan and one caller-owned UUID, and dispatches apply to the matching physical/grouped internal client. A public snapshot cannot modify that private command. An ambiguous network/server failure keeps identity only for explicit retry. HTTP4xx retires the plan. Only one write is in flight; no optimistic Task, reward, lifecycle, cache authority or historical receipt is stored. An accepted write triggers a fresh authorized read.

Explicit clear/selection changes still abort requests. Replacing or unmounting a UI owner immediately retires its generation, private plan/UUID and callbacks; an already dispatched mutation may drain its bounded, session-guarded response. This prevents the mutation's own SSE refresh from aborting a body afterHTTP200. Preview disposal still aborts, and session revocation independently aborts native transport and rejects guarded body reads. A disposed owner cannot publish data or refresh a newer owner. Synchronous subscribers can revoke the owner during publication of previewing/writing state. Two actual regressions initially observed both old API calls still being sent (38 tests,36 passed,2 failed). Generation and sequence are now rechecked immediately after publication, before calling either preview or apply. The earlier callback check after acknowledgement is preserved. All assertions remain.

The physical menu only narrows the expanded plan union before rendering its existing dialog. Grouped menus, drag and settings are not activated by this change. Full grouped UI, pointer/touch/keyboard interaction, workflow completion, column settings, clock refresh, large lists and the remaining master-plan work are separate acceptance tasks.
