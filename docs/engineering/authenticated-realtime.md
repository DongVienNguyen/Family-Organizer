# Authenticated realtime (F04-c)

The existing module refresh flow now opens `/api/realtime` with an Authorization header through the session-bound fetch adapter. Anonymous requests and valid tokens supplied only in the URL are rejected. No credential enters an EventSource URL. The connection captures the session revision before opening, verifies it at every frame/callback, and owns its reader, abort controller and reconnect timer. HTTP401/403 terminate the stream; EOF/network/protocol errors reconnect under the same still-current session. UTF8/CRLF/multiline frames are parsed with bounded chunk/frame buffers. Callbacks receive only the event type.

The server registry is constructed without storage reads or timers. Auth verification happens at admission, each emission and idle15s heartbeat. Logout rechecks immediately; expired/revoked/password/role/key/restore sessions cannot retain access at the next check. Limits are128 connections total and4 per user. Failed writes or more than64KiB pending output close the slow connection. Disconnect/end removes listeners; the last client clears the heartbeat. Lifecycle maintenance/disposal ends all streams before storage shutdown.

Domain events contain only type/timestamp: no object ID, amount, title or body. Known roles and current visibility determine recipients. Task, plan, note and document helpers preserve intended legacy permissions and fail closed for malformed sharing flags/unknown roles. Finance excludes limited roles and respects private savings goals; backups require Admin. Health/medication events also reach the patient. Update/delete routes capture prior authorized recipients before mutation, allowing a generic invalidation to remove a revoked/deleted item; subsequent private changes do not reach former viewers. This capture is transient and is not sent to clients.

Session-bound native body cancellation, reader errors and default async iterator early exit now release request ownership. Explicit `preventCancel` retains ownership while an unconsumed body remains readable, until consumption/cancellation/session change/deadline. Tests preserve current-session stream behavior as well as stale-session rejection.

Regression fixtures use synthetic auth/storage and loopback HTTP; parser/browser callback adapters never call providers. Existing assertions remain. Evidence validation requires every new realtime/policy/UI suite and the compiled production `authenticated-realtime` probe. That probe checks anonymous and URL-token rejection plus header-authenticated no-store initialization with an absolute deadline, then destroys its stream before graceful stop.

Current proof and exact SHA/run are recorded in implementation-status.md and the PR evidence comment. Cloud development tests are not Windows proof. Source/callback tests are not real browser/PWA acceptance (F05). HTTP object filtering, media binding, notification privacy, input validation, bootstrap policy, trusted proxy and dependency triage remain subsequent F04 work; no Internet-readiness claim. Windows2022 does not prove Server2019 (R02). No release/tag or VPS access/deployment.

Review corrections: stalled native responses retain their admission slot until socket close and are forcibly destroyed, not detached behind pending output. Rejected locked/released stream preconditions retain transport ownership. Completion/approval invalidates successor assignees when recurrence rotation creates a new task. See f04-c-review.md for actual RED cases and the acceptance rulings.
